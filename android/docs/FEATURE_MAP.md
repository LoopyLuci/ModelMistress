# ModelMistress: desktop to Android feature map

Status values:

- **Built, tested** – code is in place and covered by host JVM tests (`:core:test`, `:server:test`). Not yet run on a device.
- **Built, unverified** – the code compiles in the gate (`:app:assembleDebug`, `:router:assembleDebug`, native `:engine` build), but it has not run on a device.
- **Next** – planned for Android, not started.
- **Desktop only** – stays on the desktop hub. No Android plan yet.

It listens for the whole conversation, including while the model speaks, so talking over the reply stops it. Listen pauses the microphone without ending a reply that is playing. Interrupt stops the speech and End leaves the screen. A sentence that starts with "correction", "that's wrong" or "not quite" is not sent to the chat. It is saved as a correction of the last reply the owner heard: the words after the phrase, or else the next sentence. The saved record has the question, the reply, the correction and the camera's labels at the time. The phone says "Noted." A correction said while a reply is still being written is saved once that reply ends. The microphone is asked for when Live starts; the camera when it is turned on. ## Known limits

- Device runs so far: one phone (MediaTek MT6877, 8 cores, 7.7 GB RAM, Android 14). Other phones are untested.
- A desktop hub is reached over plain HTTP. Its port must be open to the phone, and Tailscale must be connected on the phone for a `100.x` address.
- Peer keys are kept in the app's private preferences, as plain text.
- The apps allow cleartext HTTP (`usesCleartextTraffic`), because Tailscale addresses are IP addresses. Use HTTPS for a name.
- CPU-only inference on arm64-v8a. No GPU or NPU path.
- One chat model and one image model are loaded at a time. Both can be in memory together, which uses more of the phone's RAM.
- Misty uses one brain, the selected chat model. Needle stays loaded once it is used, because the native runtime has no unload.
- Misty's Cactus port is a copy, not a shared module. Decision: MobileAgents' `core:misty` depends on six of its modules, including a RAG store, and ModelMistress's `core` is pure JVM with its own tool layer. Copying the parts Misty needs keeps this repo self-contained. Changes in MobileAgents do not flow here by themselves.
- Low memory: with a chat model loaded, the app's process uses about 3 GB. When another app takes the screen (the speech recognizer, the camera), Android's low-memory killer can end the app. Its draft, pending attachments and any reply in progress are lost; saved chats are kept. Seen once on the test phone.
- `llama_batch_get_one` is deprecated in the llama.cpp tree used here. It still compiles.
- Live listens while the model speaks, so talking over it stops it at once. That stop is not held, so room speech during a reply can stop it. A finished sentence is held about a second and a half before it is sent, which also delays each reply by that much; room speech that gets through can be taken back with Cancel send or "cancel". The phone matches what it hears against the last 160 words it said, so its own voice is not taken as the owner's. That matching has not been checked by ear on the phone. The recogniser also mishears words (in one test a sentence came out as "b****"), and a wrong word can only be fixed with Edit before send. The camera gives the model labels and text, not pixels, and speech depends on the phone's own recogniser and text-to-speech.
- The chat's top row (New chat, History, Files, Live) wraps onto a second line when the screen is narrow. It used to scroll sideways and hide Live; checked on the test phone after the change.
